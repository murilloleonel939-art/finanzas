### **Requisito 2: Automatización a las 4 PM (PRD §9.2)**

El sistema **actualiza precios automáticamente a las 16:00 (4 PM) hora Colombia**, sin intervención del usuario.

**Cómo funciona:**

```
Cada día a las 4 PM (21:00 UTC):
  1. Cron job se ejecuta
  2. Llama a worker-precios.mjs
  3. Worker barre TODOS los activos
  4. Actualiza precios desde Yahoo Finance
  5. Logs en logs/cron-precios.log
```

**Implementación:**
- Script: `scripts/cron-setup.sh` (ejecutable)
- Automatiza instalación del cron
- Setup: `bash scripts/cron-setup.sh`

## ⚠️ Limitaciones Conocidas

| Limitación | Impacto | Solución |
|-----------|---------|----------|
| Cron no es "catch-up" | Si servidor está apagado a las 4 PM, no se recupera | Usuario pulsador botón manual si es necesario |
| Excel sin formato | Descarga como CSV con extensión .xlsx | Instalar `npm install xlsx@latest` |
| PDF sin html2pdf | Abre en nueva ventana para imprimir | Instalar `npm install html2pdf@latest` |
| No valida zona horaria del servidor | Cron podría ejecutarse a hora equivocada | Verificar `timedatectl` en servidor |

## ✨ Decisiones de Diseño

### D32 — Exportación de datos en CSV, Excel y PDF

**Decisión:** Componente reutilizable con tres métodos de descarga

**Razón:** 
- CSV funciona sin dependencias externas
- Excel y PDF son opcionales pero disponibles
- Reutilizable en cualquier página del sistema

**Trade-off:**
- CSV siempre funciona
- Excel requiere `xlsx` package
- PDF requiere `html2pdf` o `jsPDF`

---

### D33 — Programación con cron del sistema

**Decisión:** Usar cron de Linux en lugar de setTimeout/intervalo

**Razón:**
- No depende de que la app esté corriendo
- Funciona incluso si se reinicia el servidor
- Standard en infraestructura Linux
- Fácil de monitorear y debuggear

**Trade-off:**
- Si servidor está apagado a las 4 PM, no se recupera
- Requiere acceso root o usuario con permisos de cron
- Depende de zona horaria del servidor
